# The durable A5 run (0.3.0, gate G2)

Contract assertion A5 asks that a write stays recoverable a day later. The caller may hold the receipt id, or only K. The 0.1.0 run kept one process up for 24 hours. From 0.3.0 the store is durable, so the scored run adds a restart in the middle of the window. This page is the plan; `harness/a5_durable.sh` runs it.

## What the run shows

- The planted write survives a whole-process restart. Its execution record (`GET /executions/X-n`) and its operation record (`GET /operations/K`) still answer, and the served digest equals the digest committed on day one.
- The clock is the wall clock at every step: `clock.domain` is `wall` and `clock.offset_ms` is `0` in `/build`, with control off. Nothing moved time (design rule 8).
- The build is the same before and after the restart (`build_hash` equal). Only `process.boot_id` and the journal head change.

## The build

```
tiny-tracker all --features evidence,strict-input,ledger,durable,inflight,retention \
  --data-dir $A5_DIR/data --token-dir $A5_DIR/tokens --port 4710 --backend-port 4711
```

- **Control is off.** No `--fixture-control`, so there is no fault listener and no fixture clock (CMP-33, CMP-60). The lost response is therefore client-side: the adapter reads the response off the wire and discards it (`adapter_config.py --fault client`).
- **`durable` with `strict-input`** (CMP-50). Key retention is the default 7 days, so the key is well inside retention at the 24-hour leg.
- **Fixed ports.** The plant records the MCP endpoint and the evidence base, and the restart must come back on them. Ports 47310/47311 are never used.
- **Tokens.** The backend token is generated once into `$A5_DIR/backend.token` (0600) and passed in the environment. The evidence token is generated by tiny-tracker into the token dir. No token is put on a command line or printed.
- **The contract driver** is a copy of the checkout at the pinned commit (`harness/contract.json`), with the tiny-tracker adapter beside it. The copy is kept in `$A5_DIR/driver`, because the delayed leg loads the adapter from there.

## Procedure

| Step | When | Command | What it checks |
|---|---|---|---|
| 1 | Day 1, T0 | `A5_DIR=… CONTRACT_DIR=… harness/a5_durable.sh start` | `/build`: wall clock, offset 0, control off, durability `journal`, nothing armed. The start refuses to go on otherwise |
| 2 | T0 | `harness/a5_durable.sh plant` | The driver runs A1–A5. A1–A4 are scored now. A5 is planted (`a5_plant.json`: K, the receipt id, the committed digest, `due_at` = commit + 24 h) and scored `unproven` today |
| 3 | Between T0 + 1 h and `due_at` − 1 h | `harness/a5_durable.sh restart` | First, a recount of this boot's evidence (the ledger is whole until the stop). Then SIGTERM, and a start on the same data dir, token dir and ports. Then `check`: same `build_hash`, a new `boot_id`, and `GET /operations/K` and `GET /executions/X-n` answer 200 (read-only) |
| 4 | Any time | `harness/a5_durable.sh check` | Read-only status. It writes nothing that A5 counts |
| 5 | At or after `due_at` | `harness/a5_durable.sh delayed` | The driver's `--delayed-leg` on the plant: run-id digest equality, and K-only lookup with HTTP 200. It writes `a5_delayed_result.json` next to the plant, and `/build` again (still wall clock, offset 0, control off). It refuses before `due_at` unless `A5_FORCE=1`, which is for rehearsals only and never a scored A5 |
| 6 | After 5 | `harness/a5_durable.sh recount` | `tt_recount.py` over the export, the ledger, the execution records and the journal |
| 7 | After 6 | `harness/a5_durable.sh stop` | |

Publish the run folder's `runs/<dir>` (the driver's raw outputs, `a5_plant.json` and `a5_delayed_result.json`), the `build.*.json` snapshots, the `recount*` files and `a5.log`. Check for tokens first: none should appear.

## Known limits

- **The ledger is kept in memory**, for one boot. After the restart it holds only that boot's entries. The recount taken just before the restart (step 3) is the complete four-source recount for the planting boot. The recount after the delayed leg is expected to show ledger-versus-journal disagreements for the writes made before the restart. The journal and the execution records must still agree, with digests recomputed from the committed bodies. A durable ledger is open for streams B and E (see TT-UPGRADE-2).
- **A3 stays self-attested** until driver ask (b) lands (`harness/contract.json`).
- **The contract is a draft under joint review.** A run before it freezes is a historical baseline, and it is repeated after the freeze.

## Rehearsal

The whole procedure, with `A5_FORCE=1` on the delayed leg a minute after planting, is the rehearsal recorded in TT-UPGRADE-2. It is not a scored A5. The scored run is the 24-hour one.
